# 一挪迈平台写作风格指南

全局文风以 [inm-writing 的 global-style.md](../../inm-writing/references/global-style.md) 为准；分发前读取该文件。本文件补充 X 和公众号的平台适配，不覆盖全局规则。

## 内容取舍

- 保留事实、机制和有依据的判断，也保留会影响结论的日期、前提、不确定性和风险。
- 可以有程序员式的分析习惯：拆解问题、理清因果、交代边界。正文面向普通中文读者，不引入程序员视角的代码、接口、缓存、I/O 等概念解释无关主题。
- 主题本身涉及技术时，只解释读者理解该主题所需的概念，不用另一个技术概念作类比。
- 删除不能帮助理解的聪明话、身份暗示、强凑的金句和升华。判断标准是：删掉后是否损失了事实、机制、必要限定或判断依据；没有损失也没有解释作用，就删掉。
- 类比不作固定环节。确实能降低理解成本时，才使用读者熟悉的生活例子。

## 语气与结构

- 像朋友聊天一样分享见解，半正式、口语化但不粗糙；不端架子、不说教。
- 可以用「我」表达判断，交代理由；不编造个人经历，也不强加口头禅、自嘲或幽默。
- 开头 1–2 句话进入具体事实、问题或判断，不为吸引注意夸大冲突或制造悬念。
- 短段落，每段通常 1–4 句话；按事实 → 机制 → 判断展开，不硬套模板。
- 列表和表格用于让信息更容易比较；加粗只突出核心信息。
- 英文专业术语在主题需要时保留，首次用中文解释；不混用多个领域的术语展示背景。
- 正文少用 emoji。篇幅由解释所需的信息决定，不为节奏拆成大量单句。

## 结尾

- 保留「一挪迈的思考」或「一挪迈的总结」。
- 简短交代自己的判断、取舍和适用条件，讲清楚即可停下。
- 不强制金句、开放问题、互动引导或抽象升华；已有表达仅在有助理解时保留。
- 投资文章保留 DYOR 声明。

## 平台适配

- **X Article**：优先保留已确认正文，只做必要的格式适配。表格按信息量转为图片或列表；富文本正文用 `【文件名】` 标记插图，由用户手动粘贴、插图和发布。
- **公众号**：调整标题和段落以方便手机阅读，保留表格、必要来源和判断依据，不用标题党或空泛总结补充篇幅。
- 用户只要求转换或发布准备时，不额外提供风格方向选择，也不借机重写已确认的内容。
